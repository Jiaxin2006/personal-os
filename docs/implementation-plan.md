# MVP 分步实施计划

本轮只交付审查、方案、计划和配置草案。以下路径除既有文件外均为建议新增路径；方案讨论后再创建业务代码。不会同时实施 Python、Rust 和 Swift 三套领域层。

## 开发阶段依赖

```text
一致备份 → 安装版基线/兼容 → 核心和只读适配 → 配置持久化
                                         ├→ 类别 → 汇总 → 目标
                                         └→ 周期任务
目标 + 周期任务 → 周复盘
架构讨论 → 小型桌面验证 → 选择界面技术
领域结果 + 界面路线 → 三页MVP → 导入导出与接管 → 集成/真实设备验证
```

在技术路线确认之前，第9–10项不会升级为大型界面开发。第一阶段不为金融模块建立证券、交易或收益归因表；月度复盘只是普通周期任务和手工复盘内容。

## 必须落地的验收用例

| 场景 | 输入 / 操作 | 预期 |
| --- | --- | --- |
| 科研目标独立计算 | 周一8h、周三8h、周五4h | 时长20/20h；有效天数3/5；不能整体显示全部完成 |
| 阅读频率 | 周一90min，其余0 | 1/3天，未达标 |
| 阅读日内累计 | 三个日期，各两段15min | 3/3天，达标 |
| 阅读边界 | 一日1799秒、另一日1800秒 | 分别不计、计一个有效日 |
| 跨午夜阅读 | 23:45至00:15连续阅读 | 两日各15min，本次不足以使任一日达标 |
| 不重复计时 | 一个60min活动关联两个目标 | 总时长60min；目标可各获得60min，不能加成120min工作 |
| 旧版分类选择 | 本次中途更改类别再保存 | 仍按最终类别归属整次，保留旧语义 |
| 新界面切换活动 | 科研60min后切阅读30min | 科研60、阅读30；保存和新开原子处理 |
| 月末窗口 | 2026年11月最后7天显示 | 11/23日常列表无；11/24出现；11/30截止；完整列表始终可查 |
| 逾期规则 | 月末未完成后进入下月 | 上期仍为未完成/逾期；新期有独立实例，不能覆盖 |
| 重复生成 | 同时打开两次、重复刷新、重启 | 每模板每周期只有一个实例 |
| 多月离线 | 应用关闭两个月后再启动 | 保留并补齐启用以来的实例；历史可查，日常逾期折叠 |
| 配置编辑 | 改目标或归档类别 | 历史与完成复盘仍可读；未来按新版本生效 |
| 冷启动持久化 | 创建目标、完成周期任务、保存复盘后退出 | 重开全部存在；重新生成不重复；计时按明确恢复策略继续/暂停 |
| 重启边界 | last_tick后不足60秒重启 | 排除关机间隔，与间隔是否超过60秒无关 |
| 数据兼容 | 含Reading、未知类别、recovery_events的来源 | 原ID/原始值保留；读取不崩溃；未知信息不被清除 |
| 迁移幂等 | 同一批SQLite与日志导入两次 | 时长与记录数不变；来源变更需解决冲突 |
| 故障回滚 | 保存/切换/导入时模拟失败 | 历史和状态同时成功或同时回滚；恢复包不半覆盖 |

真实设备检查与单元测试分别记录。可以用 mock 验证系统事件分支，但不得把它写成“已实测合盖/重启”。测试仅操作临时目录或备份副本，不对正在运行的个人历史执行故障注入。
