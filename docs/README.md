# Personal OS v0.1：审查与开发建议

初次审查日期：2026-11-05。当前状态：本地兼容 MVP 已实现，正在验证原生应用交付。

先看 [MVP 使用与构建说明](usage.md) 和 [并行 agent 分工与接口](agent-contract.md)。以下审查与架构文档保留原方案背景，具体已实现行为及限制以使用说明为准。

本轮检查了本仓库的全部文本源文件、安装脚本和测试，并与实际安装的 `~/.config/sketchybar` 比较；真实数据库只通过 SQLite `mode=ro` 读取。未安装、重载状态栏，未改动运行代码或真实历史。

建议保留现有计时引擎及其行为，通过兼容读取先验证每周投入与周期复盘。面向大众的 macOS 产品倾向 SwiftUI + SQLite；Tauri 是备选，不在本轮确定或重写架构。

- [默认配置示例](personal-profile.example.json)：新用户第一次打开时的类别、目标和周期任务。

阅读目标是：**每周至少 3 个不同的本地自然日，各日累计阅读至少 1,800 秒**。一天读 90 分钟只计 1 个有效日；一天两次各 15 分钟可计 1 个有效日。暂按弹性目标、独立阅读类别、不计入总工作；这些是可修改的初始假设。

这里的配置 JSON 保留为方案示例；应用实际加载 `personal_os/initial_profile.json`，初次启动后保存为可编辑的用户配置，不覆盖后续修改。

本轮最需要先处理的问题是仓库与安装版不同：安装版有 `reading` 类别、合盖外接显示器修正和真实数据库中的 `recovery_events` 表。直接用仓库版本重新安装，会覆盖前两项改动，并可能因持久化状态里的 `reading` 触发 `KeyError`。
